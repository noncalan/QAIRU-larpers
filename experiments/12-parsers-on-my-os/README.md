# Проверка парсеров на Windows

Эксперимент 12(а) сравнивает диагностику локального `guard.check` с ожиданиями из раздела 5 [исследования битых файлов](../../docs/research/04-parsing-and-broken-files.md). Отдельная копия PDF проверяет чтение из папки с пробелом и кириллицей в пути.

Запуск из корня репозитория в PowerShell

```powershell
uv run --group experiments --with pikepdf --with pypdfium2 --with msoffcrypto-tool --with olefile --with psutil python experiments/12-parsers-on-my-os/run_os_check.py
```

При каждом запуске скрипт очищает `experiments/out/fx/` и заново создаёт образцы из трёх файлов `data/input/requirements.*`. На каждый файл отводится до 60 секунд для guard и ещё до 60 секунд для парсеров. Образцы с диагностикой `ERROR` пропускают этап парсинга. Файл `docx_bomb.docx` проверяет только guard.

В `experiments/out/12/results.md` находятся версии пакетов, замеры и итоги по файлам. Полные сообщения диагностик и конец stderr каждого процесса сохраняются в `results.json` рядом с отчётом. Ожидание `none` допускает предупреждения и информационные сообщения. Итог `N/A` означает, что для guard нет проверяемого ожидания. Для `docx_bad_xml.docx` отдельно указан результат проверки исключения в python-docx.

Полнота — доля уникальных кириллических слов из `req.md` длиной от трёх букв, найденных в извлечённом тексте без учёта регистра. Память генератора измеряется с учётом дочерних процессов каждые 50 мс. Для guard и парсеров берётся пик рабочего набора Windows, а при отсутствии этого счётчика — RSS в конце этапа.
