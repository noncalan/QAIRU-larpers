# Эксперимент 23: живой проход поиска и перенос в JSON (issue #18)

Проверка шага 4 агента на `data/input/requirements.md` одним живым проходом: работает ли разбор ответа кодом и нужен ли перенос в JSON моделью на каждом проходе (D-010) или только запасным путём (рекомендация интегратора в #18).

Запуск: `uv run python experiments/23-search-pass/record.py`. Ответы сохраняются в `experiments/out/23/` (в git не идут) в формате `claude -p --output-format json`; повторный запуск берёт их с диска и модель не вызывает. Копии ответов лежат в `tests/fixtures/llm/search/live/`, на них работают тесты `tests/test_search.py`.

## Что сделано (25.11.2026, 2 живых вызова через подписку)

1. `search()` агента, профиль `quick`: один проход Opus 5.5 (`claude-opus-5-5`) `medium`, промпт #14 (`prompts/search_system.md`, `prompts/search_user.md`) как есть, без JSON-схемы.
2. Перенос **всех** находок того же прохода в JSON через Haiku 5.5 (`claude-haiku-5-5`) `medium` по `prompts/search_transfer_system.md` и `TRANSFER_SCHEMA`, чтобы сравнить с разбором кодом. В агенте этот вызов делается только для находок, которые код не разобрал.

## Результат

| | Проход Opus `medium` | Перенос Haiku `medium` (все находки) |
|---|---|---|
| Время | 220 с | 76 с |
| Токены вывода | 26 751 | 23 147 |
| Цена по тарифу API (оплачено подпиской) | $0,659 | $0,017 |

Разбор ответа прохода кодом (`search_parse.py`):

- находок в ответе 49, код разобрал **49 из 49**, перенос моделью не понадобился;
- ID блоков, которых нет в документе: 0; у всех 49 находок есть суть (`title`), объяснение, ID блоков и цитата;
- цитат 66, найдено в документе кодом (`locate_quote`) **66 из 66**;
- 31 находка уровня требования и 18 уровня набора; сценарий у 15, «чего не хватает для теста» у 35, «неясно» у 2.

Сравнение с переносом Haiku тех же 49 находок:

| Поле | Совпало с кодом |
|---|---|
| Свойство | 48 из 49 |
| Тип дефекта, вердикт, важность, «мешает тесту» | 49 из 49 |
| ID блоков (после раскрытия диапазона «B075–B083») | 49 из 49 |
| Цитаты | 43 из 49 |

- Единственное расхождение по свойству: модель написала в строке два свойства («Feasible …, Verifiable …»), код берёт первое, Haiku выбрал второе.
- Цитаты Haiku хуже исходных: 61 из 66 найдены в документе против 66 из 66 у кода. Haiku добавлял в цитату служебную разметку строки таблицы («Format: integer», «Swagger: —», ячейки целой строки), хотя промпт это запрещает.
- Тот же проход через `FakeLLM` из сохранённого файла даёт тех же кандидатов (проверка в конце скрипта).

Сквозной прогон конвейера на этом ответе (`--backend fake`, папка фикстур с этим проходом, `--passes 1`): код 0, 49 кандидатов, 48 находок после заглушки слияния, отброшено 0, доля сверенных цитат 100 %. У двух находок верификатор поправил место: модель указала соседний блок (например, строку таблицы под заголовком, который процитировала).

## Вывод

Основной путь переноса в `CandidateFinding` делает код: на настоящем ответе он разбирает всё, бесплатно, за миллисекунды и не портит цитаты. Haiku остаётся запасным путём для находок, которые код не разобрал (нет цитаты, свойства или типа дефекта, сбит формат), с одним повтором. Это отклонение от D-010 (там Haiku переносит каждый проход): экономия ~$0,02 и ~80 с на проход, а главное, цитаты остаются дословными.

Ограничение замера: один проход на одном документе. Отклонения формата на других документах покрыты тестами разбора (`tests/test_search_parse.py`) и запасным путём через Haiku.
