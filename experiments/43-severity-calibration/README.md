# Эксперимент 43: калибровка важности по разметке precision

26.11.2026, issue #115. Вопрос: можно ли сократить обязательный список находок (критичные и важные), не теряя настоящие. Расчёт идёт без вызовов модели: по готовой разметке #49 (две модели вслепую, не люди) и по `report.json` пяти размеченных прогонов с одним проходом поиска (`checklists/cl/run-1`, `recall/v2/run-1` и `run-2`, `recall/v3/run-1` и `run-2`). Эталон `docs/gold` не используется.

Разметка пилота (`tests/fixtures/e2e/md`, три прохода) в расчёт не идёт: запись по этому пути с тех пор перезаписана, и разметка ей не соответствует.

## Что увидели

Метка разметчика «спорно» по определению значит «проблема есть, но разработку и тест почти не задевает». Это то же, что «незначительно» у агента: находки, которые агент сам назвал незначительными, разметчики почти никогда не называют настоящими.

Среди «важных» есть две группы, где настоящих мало (вывод `whatif.py`):

| Группа «важных» находок | Находок | Настоящих (оба разметчика) |
|---|---:|---:|
| Дефект формы с отметкой модели «мешает тесту» (терминология, пустое поле, дубль и т. п.), кодом не подтверждён | 20 | 2 |
| Модель сама дала подсказку важности «низко», кодом не подтверждено | 23 | 4 |
| Остальные «важные» | 123 | 66 |

До правки подсказка модели только не давала поставить «критично» без её согласия, понизить «важно» до «незначительно» она не могла.

## Правила

- **R1.** Дефект формы не выше «незначительно», даже с отметкой модели «мешает тесту».
- **R2.** Подсказка модели «низко»: не выше «незначительно».

Оба правила не трогают находку, которую подтвердил код: правило линтера, которое само ставит «мешает тесту» (например, маркер «TBD» в требовании), или пример-свидетель, сверенный кодом. Документ с недописанными требованиями не должен получать зелёный свет из-за мнения модели. R2 не действует на находку «посторонняя инструкция»: такой текст может сам попросить модель поставить «низко».

## Что это даёт

Расчёт «что если» (`whatif.py`, пять прогонов):

| Правило | Обязательный список, находок на прогон | Строгая precision списка | Настоящих вне списка, на прогон |
|---|---:|---:|---:|
| до правки | 39,8 | 49,7 % | 0,2 |
| R1 | 35,8 | 54,2 % | 0,6 |
| R2 | 35,2 | 54,0 % | 1,0 |
| R1 + R2 | 31,2 | 59,6 % | 1,4 |

Проверка настоящим кодом (`replay_check.py`): те же пять прогонов пересобраны через `--backend replay`, находки сопоставлены со старой разметкой по `merged_id`.

| Прогон | Список до | Precision до | Список после | Precision после | Настоящих вне списка: до → после |
|---|---:|---:|---:|---:|---:|
| checklists/cl/run-1 | 37 | 45,9 % | 28 | 57,1 % | 0 → 1 |
| recall/v2/run-1 | 43 | 48,8 % | 33 | 60,6 % | 0 → 1 |
| recall/v2/run-2 | 43 | 46,5 % | 34 | 52,9 % | 0 → 2 |
| recall/v3/run-1 | 39 | 46,2 % | 32 | 50,0 % | 0 → 2 |
| recall/v3/run-2 | 37 | 62,2 % | 29 | 79,3 % | 1 → 1 |
| **В среднем** | **39,8** | **49,7 %** | **31,2** | **59,6 %** | **0,2 → 1,4** |

На двух прогонах текущего промпта (v3): список с 38,0 до 30,5 находки, строгая precision списка с 53,9 % до 63,9 %. Для сравнения: строгая precision одного промпта по всему его списку 53,5 % (важность у него не размечена).

## Оговорки

- Находки не удаляются, перенесённые остаются в отчёте с важностью «незначительно». Строгая precision по всем находкам (42,4 % на v3) и recall по эталону от правил не меняются, меняется только обязательный список. Отдельный блок «Незначительные замечания (по желанию)» в отчёте делает PR #114 (#112), в этой ветке его нет.
- Правила подобраны по разметке одного документа. Слов и чисел документа в них нет, но проверки на чужих документах (#48) нет: на холдауте нет разметки.
- 1,2 настоящей находки на прогон дополнительно уходит из обязательного списка (0,2 → 1,4).
- Пять прогонов трёх версий промпта поиска (до #111, v2, v3): это не пять повторов одной версии. Разброс между прогонами большой (precision списка после правки от 50,0 % до 79,3 %).
- Критичные находки правила не затрагивают: подсказка «низко» и раньше не давала поставить «критично». Но «важная» находка с подсказкой «низко» раньше делала светофор жёлтым, а теперь нет.
- Правка меняет важность и номера находок на входе шага «вопросы автору», поэтому вопросы в записях e2e перезаписаны (`tests/fixtures/e2e/README.md`).
