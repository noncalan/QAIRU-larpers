# Эксперимент 43: калибровка важности по разметке precision

26.11.2026. Вопрос: можно ли сократить обязательный список находок (критичные и важные), не теряя настоящие. Вызовов модели нет: считаем по готовой разметке #49 (две модели вслепую, не люди) и по `report.json` шести размеченных прогонов. Эталон `docs/gold` не используется.

## Что увидели

Метка разметчика «спорно» по определению значит «проблема есть, но разработку и тест почти не задевает». Это то же, что «незначительно» у агента. Из 68 находок, которые агент сам назвал незначительными, оба разметчика назвали настоящими 3.

Среди «важных» есть две группы, где настоящих мало:

| Группа «важных» находок | Находок | Настоящих (оба разметчика) |
|---|---:|---:|
| Дефект формы с отметкой «мешает тесту» (терминология, пустое поле, дубль и т. п.) | 26 | 4 |
| Дефект смысла, модель сама дала подсказку важности «низко» | 26 | 6 |
| Остальные «важные» (дефект смысла, подсказка «средне» или её нет) | 147 | 79 |

Сейчас подсказка модели только не даёт поставить «критично» без её согласия (`severity.py`, `UNCONFIRMED_CRITICAL_MAX_SEVERITY`), понизить «важно» до «незначительно» она не может.

## Два правила и что они дают

- **R1.** Дефект формы не выше «незначительно», даже с отметкой «мешает тесту».
- **R2.** Подсказка модели «низко»: не выше «незначительно».

Вывод `whatif.py`:

| Срез | Правило | Обязательный список, находок на прогон | Строгая precision списка | Настоящих вне списка, на прогон |
|---|---|---:|---:|---:|
| все 6 прогонов | сейчас | 39,7 | 51,3 % | 0,5 |
| | R1 | 35,3 | 55,7 % | 1,2 |
| | R2 | 33,8 | 55,7 % | 2,0 |
| | R1 + R2 | 31,0 | 60,2 % | 2,2 |
| recall/v3, 2 прогона | сейчас | 38,0 | 53,9 % | 0,5 |
| | R1 + R2 | 30,0 | 65,0 % | 1,5 |

Для сравнения: строгая precision одного промпта (весь его список, важность у него не размечена) 53,5 %.

## Оговорки

- Находки не удаляются: перенесённые остаются в отчёте в блоке «Незначительные замечания (по желанию)» (#112). Строгая precision по всем находкам (42,4 % на v3) от правил не меняется, меняется только обязательный список. Recall по эталону тоже не меняется.
- Правила подобраны по разметке одного документа. Слов и чисел документа в них нет, но проверки на чужих документах (#48) нет: на холдауте нет разметки.
- 1,7 настоящей находки на прогон уходит из обязательного списка в блок «по желанию» (R1 + R2, шесть прогонов).
- Шесть прогонов разных версий промпта (e2e с тремя проходами, cl, v2, v3): это не шесть повторов одной версии.
- Правка `severity.py` меняет отчёты записей e2e и, возможно, вопросы автору (кандидаты зависят от находок): записи и снапшоты придётся перезаписать. В этом эксперименте поведение агента не меняется.

## Итог: правка в коде (#115)

Оба правила внесены в `src/validator/severity.py` с одним отличием от расчёта: находку, которую нашло или подтвердило правило линтера, они не понижают. У линтера отметку «мешает тесту» ставит код (например, маркер «TBD» в требовании), и документ с недописанными требованиями не должен получать зелёный свет. В размеченных прогонах таких находок среди перенесённых нет, цифры расчёта те же.

Проверка настоящим кодом: пять размеченных прогонов с одним проходом пересобраны через `--backend replay`, находки сопоставлены со старой разметкой по `merged_id`.

| Прогон | Обязательный список до | Строгая precision до | Обязательный список после | Строгая precision после | Настоящих среди незначительных: до → после |
|---|---:|---:|---:|---:|---:|
| checklists/cl/run-1 | 37 | 45,9 % | 28 | 57,1 % | 0 → 1 |
| recall/v2/run-1 | 43 | 48,8 % | 33 | 60,6 % | 0 → 1 |
| recall/v2/run-2 | 43 | 46,5 % | 34 | 52,9 % | 0 → 2 |
| recall/v3/run-1 | 39 | 46,2 % | 31 | 51,6 % | 0 → 2 |
| recall/v3/run-2 | 37 | 62,2 % | 29 | 79,3 % | 1 → 1 |
| **В среднем** | **39,8** | **49,7 %** | **31,0** | **60,0 %** | **0,2 → 1,4** |

Критичные находки и красный светофор правила не затрагивают: подсказка «низко» и раньше не давала поставить «критично».
