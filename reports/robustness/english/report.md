### Q-01 · P0 · бизнес · срок одноразового кода
**Вопрос.** Посылку разместили в понедельник в 10:00, клиент вводит код в среду в 12:00: ячейка откроется?

**Где в документе.**
- «The customer shall open the compartment with a one-time code valid for 48 hours.» (раздел «Parcel Locker Service: Software Requirements › 2. Functional requirements», таблица 1, строка 3, ячейка 2, колонка «Requirement»)
- «A one-time code shall remain valid for 72 hours after the parcel is placed.» (раздел «Parcel Locker Service: Software Requirements › 3. Non-functional requirements», строка 24)

**Почему важно.** FR-03 и NFR-02 задают разный срок кода. От срока зависят открытие ячейки, момент автоматического освобождения и ожидаемый результат теста. Момент отсчёта указан только в NFR-02 (от размещения посылки).

| Вариант | Правило | Что поменять |
|---|---|---|
| A | Нет: код действует 48 часов с момента размещения посылки | В FR-03 указать 48 часов и момент отсчёта, NFR-02 удалить |
| B | Да: код действует 72 часа с момента размещения посылки | В FR-03 заменить 48 на 72 и указать момент отсчёта, NFR-02 удалить как дубль |
| Другое | ___ | |

**Если не ответить.** Команда возьмёт 72 часа из NFR-02, где указан момент отсчёта. Если верный срок 48 часов, ячейки будут лишние сутки заняты невостребованными посылками.

### Q-02 · P0 · бизнес · истечение кода с посылкой
**Вопрос.** Срок кода истёк, посылка всё ещё лежит в ячейке: что происходит с ячейкой и посылкой?

**Где в документе.**
- «The system shall release the compartment automatically when the code expires» (раздел «Parcel Locker Service: Software Requirements › 2. Functional requirements», таблица 1, строка 4, ячейка 2, колонка «Requirement»)

**Почему важно.** Ячейку с посылкой нельзя сделать свободной, а порядок возврата посылки не описан. Кроме того, нет списка состояний ячейки и переходов между ними, в том числе освобождения после того, как клиент забрал посылку.

| Вариант | Правило | Что поменять |
|---|---|---|
| A | Ячейка остаётся занятой до изъятия посылки курьером по отдельному коду, затем становится свободной _(вариант для обсуждения)_ | Добавить состояние «ожидает изъятия», код изъятия для курьера и таблицу переходов состояний |
| B | Клиенту выдаётся новый код на дополнительный срок, после него посылку изымает курьер _(вариант для обсуждения)_ | Добавить продление кода, его срок и последующее изъятие курьером |
| C | Ячейка сразу считается свободной, посылку вынимает управляющий домом | Описать действия управляющего с посылкой и то, как ячейка доступна для резерва до её изъятия |
| Другое | ___ | |

**Если не ответить.** Команда оставит ячейку занятой до изъятия курьером. Если бизнес ждал другого, сценарий возврата придётся переделывать.

### Q-03 · P0 · бизнес, архитектор · момент размещения посылки
