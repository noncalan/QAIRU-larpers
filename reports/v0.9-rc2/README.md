# Кандидат v0.9-rc2: отчёт агента по `requirements.pdf`

Второй кандидат к сдаче (#54). Отчёт о проверке выданного документа собрал агент на коде `v0.9-rc2` (коммит `f69ee0f` в `main`): в нём правки по ревью RC1 (#118–#127) и по ревью кода Fable (#139–#145), которые влиты к этому коммиту. Отчёт не правили руками: файлы ниже записал агент.

**Живых прогонов агента для RC2 не было.** Ответы модели взяты из записей живых прогонов, которые лежат в `run/` рядом с каждым отчётом. Код после модели (разбор ответов, слияние, верификатор цитат, вопросы автору, отчёт, самопроверка) работал на `f69ee0f`. Паспорт отчёта говорит об этом прямо: «записанные ответы (replay): из записи 8 из 8 ответов, модель не вызывалась», а строка «Запись ответов модели» называет папку записи, время записи и способ вызова.

**Сборка.** Из чистого дерева на `f69ee0f` с локальным тегом `v0.9-rc2` (в паспорте версия без `-dirty`), секунды и без сети:

```bash
uv run validator data/input/requirements.pdf reports/v0.9-rc2/report.pdf --backend replay --replay reports/v0.9-rc2/run
uv run validator data/input/requirements.md reports/v0.9-rc2/formats/md/report.md --backend replay --replay reports/v0.9-rc2/formats/md/run
uv run validator data/input/requirements.docx reports/v0.9-rc2/formats/docx/report.md --backend replay --replay reports/v0.9-rc2/formats/docx/run
uv run python -m evals.formats reports/v0.9-rc2/formats/md reports/v0.9-rc2 reports/v0.9-rc2/formats/docx --out reports/v0.9-rc2/formats.md
```

Replay в папку записи переписывает `run/calls.jsonl` строками replay, поэтому после сборки запись вернули как была (копия из `tests/fixtures/e2e/<формат>/run`). Тег `v0.9-rc2` в GitHub ставит владелец репозитория на коммит `f69ee0f`: из облачной сессии теги не пушатся.

Витрина устойчивости пересобрана на том же коде агента: [`reports/robustness/`](../robustness/README.md), все 24 случая с ожидаемым кодом и диагностикой. В её паспортах версия `v0.9-rc2-1-g712cb0c`: это коммит этого PR поверх `f69ee0f`, в нём только новые записи и скрипт витрины, `src/` тот же. Записи английского и двуязычного документов сделаны заново живым прогоном 27.11 с 03:27 до 03:41 по Астане (подписка, профиль `quick`, по 7 вызовов, по тарифу API $1,39 и $1,20). Теперь они находятся по ключу запроса, без предупреждения `LLM-016`. Запись документа с командами модели внутри (`injection`) старая и по-прежнему проигрывается по номеру вызова.

### Что изменилось по сути (PDF)

**Вывод тот же:** 🔴 начинать разработку и тестирование нельзя. Критичных 6 вместо 8, и все 6 это те же дефекты, что среди 8 критичных RC1: месяц покупки по Ф-2 и по примеру, открытый состав расходов, выключенное уведомление в решении об отправке, «один push в месяц» против push после смены порога, нет операции чтения настройки, 400 или 200 с `ERROR` для неверной суммы. Ещё два критичных RC1 в RC2 есть, но с важностью «важно»: порог ниже накопленной суммы (F-17) и события процессинга (F-14). Модель в новой записи подсказала для них «важно», а правило «мешает написать тест-кейс» после #116 не поднимает важность выше подсказки модели (это видно в карточке: «подсказка модели «важно»: не выше «важно»»).

**Находок меньше из-за новой записи, а не из-за кода.** Ответы модели RC1, проигранные на коде RC2, дают 55 находок, 53 нарушения и 8 критичных (больше, чем в самом RC1: слияние после #124 не склеивает разные дефекты). В записи RC2 проход поиска сам выдал меньше кандидатов: 48 против 55. Сравнение кодом (`evals.formats`, перекрытие цитат и группа свойства) находит 39 общих находок, 14 только в RC1 и 9 только в RC2. Вручную среди них ещё около шести пар это один дефект с другой цитатой или свойством (идентификатор карты в URL, «прежнее состояние», Content-Type без тела, пересчёт валюты, открытый перечень кодов, выключенное уведомление). Остаются только в RC1: какой месяц у «суммы за месяц», держатель и владелец карты, получение push не контролируется, структура ответа 400, «200 Created», владельцы требований, два обязательства в Ф-1. Только в RC2: «в момент покупки» против учёта только проведённых операций, sequence-диаграмма без возврата и проверок. Это разброс модели между двумя живыми прогонами; его отдельно меряет стабильность (#51).

Ответы RC1 на коде RC2 проиграны флагом разработки `--replay-by-position` (запись RC1 старше #133, ответы шагов после поиска подставлены по номеру вызова), поэтому цифры шагов после поиска там приблизительные; находки поиска и слияние честные.

**Форматы разошлись сильнее, чем в RC1:** нарушений 43 (MD), 46 (PDF) и 54 (DOCX), критичных 4, 6 и 6. Каждый формат это отдельный живой прогон, и проход поиска DOCX в этой записи выдал больше кандидатов. Общих для трёх форматов находок 37 (в RC1 38), подробно в [`formats.md`](formats.md). Время MD в `formats.md` (844 с) включает `clarify.1`, в таблице выше нет.

**Вопросы автору:** 14 вместо 15. P0 теперь только у вопросов, без ответа на которые нельзя начинать (#122, #130): 6 P0 и 8 P1 вместо 15 P0. Один вопрос самопроверка сняла: ответ есть в документе, цитату-ответ код сверил (`LLM-053`). У четырёх карточек код убрал связи с находками без общей цитаты или требования (`LLM-051`).

**Что поменял код после модели** (видно в отчёте, хотя ответы модели те же, что в записи):

- цитаты из блоков-примеров получают раздел своего блока, а не раздел требования (#119);
- значения из ячеек таблиц в попытке теста подтверждаются по ячейке документа и не становятся пропуском (#120); пропуск остаётся только там, где модель не дала цитаты (в RC2 так у 4 значений и 3 чисел ожидаемого результата, `LLM-045`);
- матрица покрытия честная: части без проверки модели помечены, колонка «Набор» (#118, #126, #134);
- первая страница показывает все критичные, паспорт без внутреннего жаргона (#123, #125, #131, #135);
- противоречие без примера-свидетеля называется неполнотой (#137): на ответах RC1 противоречий 6 вместо 8, в RC2 их 4;
- самопроверка отчёта: 12 проверок вместо 8, добавились светофор, первая страница, ссылки F/R/Q и паспорт (#141, #151), все пройдены;
- паспорт replay называет запись и сколько ответов из неё взято (#156).
