# Демо «было → стало»: агент ведёт ТЗ от версии к версии

Сцена для финала на 2–3 минуты. Аналитик получил отчёт агента, исправил ТЗ и хочет знать: что закрыто, что осталось и не сломал ли он что-то правками. Всё на сцене идёт **без интернета и без модели**: прогоны агента воспроизводятся из записанных ответов (replay, около секунды), а сравнение модель не вызывает вообще.

Как устроено сравнение и что значат классы находок: [`docs/version-diff.md`](../../docs/version-diff.md).

## Что здесь лежит

| Файл | Что это |
|---|---|
| `../../data/input/requirements.md` | версия 1: исходное ТЗ |
| `requirements-v2.md` | версия 2: то же ТЗ после правок аналитика |
| `v1/`, `v2/` | отчёты агента по обеим версиям (`report.md`, `report.json`, `questions.yaml`) и записанные ответы модели (`run/`) |
| `diff.md`, `diff.json` | результат `validator-diff` |

Обе версии проверены живыми прогонами 26.11.2026 одним и тем же кодом агента (коммит `6fa0596`, профиль `standard`, один проход), поэтому разница между отчётами не от версии агента.

| Прогон | Длительность | Цена по тарифу API | Требований | Находок | Критичных | Светофор |
|---|---|---|---|---|---|---|
| v1 | 16,5 мин | $3.37 | 60 | 50 | 4 | 🔴 |
| v2 | 14 мин | $3.01 | 58 | 56 | 4 | 🔴 |

## Что правили в версии 2

Правки сделаны только по отчёту агента (находки релиз-кандидата `reports/v0.9-rc1/`), в эталон никто не смотрел.

| Правка | Какую находку закрывает |
|---|---|
| Месяц покупки: вместо «в Алматы» часовой пояс Asia/Almaty (UTC+5) | часовой пояс задан названием города |
| Критерий приёмки на стыке месяцев приведён в соответствие с правилом «по дате совершения» | **критичная**: пример противоречит требованию |
| Закрытый перечень: что входит в расходы и что нет | открытый перечень операций |
| Отклонённая сумма возвращается только с кодом 400, у ответа 200 одно тело | **критичная**: ошибка суммы возвращается с кодом 200 |
| Ответ 200 назван OK, а не Created | неверное название кода |
| Убран Content-Type у запроса без тела | заголовок при отсутствии тела |
| **Намеренная ошибка:** добавлена фраза «Экран уведомлений открывается быстро и без заметных задержек» | новая неоднозначность, чтобы показать регрессию |

Посмотреть правки: `git diff --no-index data/input/requirements.md examples/diff-demo/requirements-v2.md`.

## Что показало сравнение

| Показатель | Значение |
|---|---|
| Исправлено | **5 из 50**, критичных **2 из 4** |
| Осталось | 41, критичных 3 |
| Новое на изменённых местах | **2**: намеренная фраза про «быстро» поймана, вторая находка про неполный перечень ответов 400 |
| Не засчитано: пропало без правки | 4 |
| Не засчитано: новое на неизменённом месте | 13 |
| Светофор | 🔴 → 🔴: начинать разработку пока нельзя |

Что здесь важно для рассказа:

- **Агент не засчитал себе лишнего.** В новом отчёте нет 9 старых находок, но исправленными названы 5: у остальных 4 текст документа не менялся, это модель в этот раз их не отметила. Наивное сравнение «было в отчёте, теперь нет» записало бы аналитику 9 исправлений.
- **Регрессия поймана.** Фраза, которую «аналитик» добавил вместе с правками, сразу попала в отдельный блок как непроверяемая.
- **Правка, которая не помогла, тоже видна.** Требование про состав расходов переписали, но находка про покупки в иностранной валюте осталась: отчёт пишет «требование изменено, но находка не закрыта».
- **Честный итог.** Светофор остался красным: две критичные закрыты, но три остались, и одну критичную (push не связан с переключателем) модель нашла только во втором прогоне на нетронутом месте. Она показана отдельно, как нестабильность модели, а не как вина правок.

Для сравнения, шум модели в чистом виде: два прогона одного и того же документа разными версиями агента (`reports/v0.9-rc1` и `v1/`) дают 0 исправлено, 42 осталось, 11 «пропало» и 8 «новых». Без разделения по месту правки это выглядело бы как 11 исправлений в документе, который никто не трогал.

## Сценарий показа (2–3 минуты)

Команды из корня репозитория. Ничего не требует сети.

**Шаг 1. «Было» (30 секунд).** Агент проверяет исходное ТЗ. На сцене это replay записанного прогона, около секунды.

```bash
uv run validator data/input/requirements.md out/demo/v1/report.md --replay examples/diff-demo/v1/run
```

Сказать: «Красный светофор, 4 критичных нарушения, начинать разработку нельзя. Отчёт уходит аналитику». Открыть первую страницу `out/demo/v1/report.md`.

**Шаг 2. Аналитик правит ТЗ (30 секунд).**

```bash
git diff --no-index --stat data/input/requirements.md examples/diff-demo/requirements-v2.md
git diff --no-index --word-diff data/input/requirements.md examples/diff-demo/requirements-v2.md | head -40
```

Сказать: «Он исправил шесть мест по отчёту. И, как бывает в жизни, заодно дописал одну фразу от себя».

**Шаг 3. «Стало» (30 секунд).** Агент проверяет новую версию.

```bash
uv run validator examples/diff-demo/requirements-v2.md out/demo/v2/report.md --replay examples/diff-demo/v2/run
```

Сказать: «Снова красный, и находок даже больше, 56 против 50. По двум отчётам непонятно, стало лучше или хуже. Для этого есть сравнение».

**Шаг 4. Сравнение (1 минута).** Мгновенно, модель не вызывается.

```bash
uv run validator-diff out/demo/v1/report.json out/demo/v2/report.json out/demo/diff.md \
  --json out/demo/diff.json \
  --old-doc data/input/requirements.md --new-doc examples/diff-demo/requirements-v2.md
```

Открыть `out/demo/diff.md` и пройти первую страницу сверху вниз:

1. «Исправлено 5 из 50, критичных 2 из 4»: работа аналитика посчитана.
2. Раздел 3.2 «Новое на изменённом месте»: фраза про «быстро» поймана, это та самая лишняя правка.
3. Раздел 4 «Нестабильность модели»: «мы честно не засчитываем то, чего аналитик не правил».
4. Раздел 3.1: три критичные остались, поэтому ответ на вопрос «можно ли начинать разработку» всё ещё «нет», и видно, что именно править следующим кругом.

**Шаг 5. Как это живёт у банка (20 секунд).** Показать [`ci/gitlab-ci.example.yml`](../../ci/gitlab-ci.example.yml): та же пара команд на каждый merge request с документом, отчёты артефактами, красный светофор или новая критичная находка от правки останавливают слияние.

Запасной вариант, если на сцене что-то пойдёт не так: готовые `v1/report.md`, `v2/report.md` и `diff.md` лежат в этой папке.

## Как пересобрать демо живыми прогонами

```bash
uv run validator data/input/requirements.md examples/diff-demo/v1/report.md --profile standard --max-budget-usd 5
uv run validator examples/diff-demo/requirements-v2.md examples/diff-demo/v2/report.md --profile standard --max-budget-usd 5
cd examples/diff-demo && uv run validator-diff v1/report.json v2/report.json diff.md --json diff.json \
  --old-doc ../../data/input/requirements.md --new-doc requirements-v2.md
```

Два живых прогона, около 30 минут и $6–7 по тарифу API (через подписку `claude -p`). Цифры после пересборки будут другими: модель недетерминирована, и именно поэтому сравнение отделяет исправления от шума.
