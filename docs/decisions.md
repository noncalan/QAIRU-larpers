# Журнал решений

Короткие записи: что решили, почему, какие были альтернативы. Новые записи сверху. Крупные архитектурные решения можно оформлять скиллом `architecture-decision-records` в `docs/adr/`.

## D-005 · 25.11 · Порядок работы: исследование → идея → план

Сначала около часа исследования (`docs/research/`), затем 1–2 часа на выбор идеи вместе, затем общий план и issues. Предложение Claude (ждёт подтверждения команды): пока идёт обсуждение идеи, параллельно делать части, нужные при любой идее: чтение файлов и обработку битых файлов, скрипт оценки по эталону.

## D-004 · 25.11 · Разделение исследования

Claude с субагентами делает «кабинетное» исследование по источникам (темы 01–09 в `docs/research/README.md`). helknow делает практическую часть, которую может сделать только человек со своим ключом и компьютером: ключ Gemini и реальные лимиты, базовый прогон «один промпт», бенчмарк парсеров на наших файлах, замер ручного ревью.
