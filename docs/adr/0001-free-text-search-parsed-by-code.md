# ADR-0001: Поиск пишет свободный текст, разбирает его код, Haiku только запасной путь

**Дата:** 2026-11-25 (записано задним числом 2026-11-26)
**Статус:** принято
**Кто решал:** Нурдаулет (D-010), отклонение от D-010 предложил интегратор в #18 по замеру
**Журнал:** D-010 в [`docs/decisions.md`](../decisions.md)

## Контекст

Проход поиска дефектов — главный и самый дорогой вызов агента. Код дальше нуждается в структуре: ID блоков, цитата, свойство стандарта, тип дефекта, вердикт. Самый простой путь — попросить у модели строгий JSON по схеме (`claude -p --json-schema`). Замер 25.11 показал цену этого пути: в строгом JSON модель рассуждает в 3–5 раз меньше и находит меньше. Opus 5.5 `medium` нашёл 73 % эталона в JSON против 93 % свободным текстом ([исследование 21](../research/21-model-and-effort.md), TL;DR).

## Решение

Проход поиска (Opus 5.5) отвечает свободным текстом без схемы, но в строгом текстовом формате: раздел «Находки», заголовок «#### Н-k», строки «- Поле: значение» ([`prompts/search_system.md`](../../src/validator/prompts/search_system.md)). Ответ разбирает код ([`search_parse.py`](../../src/validator/search_parse.py)) бесплатно и детерминированно. Только находки, которые код не разобрал, переносит в JSON Haiku 5.5 `medium` ([`search_transfer.py`](../../src/validator/search_transfer.py)), и каждая запись возвращается на место своего фрагмента.

## Альтернативы

### Строгий JSON в самом проходе

- **Плюсы:** один вызов, разбор не нужен.
- **Минусы:** −20 п. п. эталона на том же effort (73 % против 93 %).
- **Почему нет:** полнота поиска важнее одного лишнего шага разбора.

### Свободный текст и перенос каждого прохода в JSON моделью (как в D-010)

- **Плюсы:** модель переноса понимает любые отклонения формата.
- **Минусы:** на живом проходе ([эксперимент 23](../../experiments/23-search-pass/README.md)) код сам разобрал 49 из 49 находок и нашёл в документе 66 из 66 цитат; Haiku в одной из двух записей испортил 5 цитат из 66 (добавил разметку строки таблицы). Плюс около 80 с и $0,02 на проход.
- **Почему нет:** код точнее на цитатах и бесплатен, а Haiku остаётся страховкой.

## Последствия

### Хорошее

- Поиск думает в полную силу, разбор ответа воспроизводим и покрыт тестами (`tests/test_search_parse.py`).
- Цитаты от прохода доходят до верификатора дословно, без пересказа второй моделью.
- Вызов Haiku случается редко, поэтому обычный прогон обходится без него.

### Плохое

- Формат ответа — неявный контракт между промптом и регулярками разбора: правка промпта требует проверки разбора.
- Модель переноса видит документ с ID блоков, это лишние токены входа, когда она нужна.

### Риски

- Другой документ или другая модель собьют формат. Защита: запасной путь через Haiku с одним повтором, потерянные находки названы в диагностике `LLM-033`, тесты разбора на отклонениях формата.
