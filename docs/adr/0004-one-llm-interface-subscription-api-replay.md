# ADR-0004: Один интерфейс модели: подписка, SDK и replay

**Дата:** 2026-11-25 (записано задним числом 2026-11-26)
**Статус:** принято
**Кто решал:** Нурдаулет (D-006 Claude API, D-008 подписка до сдачи, D-009 ключ не пополняем)
**Журнал:** D-006, D-008, D-009 в [`docs/decisions.md`](../decisions.md)

## Контекст

Модель агента — Claude (D-006). Оплаченного ключа API у команды нет, и к сдаче его не пополняем (D-009): разработка, eval и финальный отчёт идут через подписку командой `claude -p`. Жюри не сможет запустить агента через нашу подписку, а ключа Claude у него может не быть. Вызовы дорогие и медленные (проход 2–8 минут), лимиты подписки общие с работой команды, тесты и CI не должны ходить в сеть.

## Решение

Все шаги вызывают модель через протокол `LLMClient.call(LLMRequest) -> LLMResponse` ([`llm/base.py`](../../src/validator/llm/base.py)) и не знают, какой бэкенд работает:

- `cli` — подписка `claude -p` ([`claude_cli.py`](../../src/validator/llm/claude_cli.py)), из пустой временной папки, без инструментов, без ключей и `CLAUDE_EFFORT` в окружении;
- `api` — SDK `anthropic` с ключом из `.env` ([`anthropic_api.py`](../../src/validator/llm/anthropic_api.py)), те же промпты и схемы;
- `replay` — ответы из папки `run/` прошлого прогона ([`replay.py`](../../src/validator/llm/replay.py)), без модели и без ключа;
- `fake` — фикстуры для тестов.

Поверх любого бэкенда `RecordingClient` ([`calllog.py`](../../src/validator/llm/calllog.py)) одинаково делает кеш, лимит цены, один повтор и запись каждого вызова. `--backend auto` выбирает подписку, затем ключ, затем replay; если нет ни команды `claude`, ни ключа, ни записи, пишет отчёт с `LLM-001`.

## Альтернативы

### Только SDK `anthropic`

- **Плюсы:** один путь, официальные возможности API (строгий JSON, Citations).
- **Минусы:** без оплаченного ключа агент не работает вовсе.
- **Почему нет:** противоречит D-009; у жюри тоже может не быть ключа.

### Только подписка `claude -p`

- **Плюсы:** бесплатно для команды.
- **Минусы:** жюри и банк не запустят агента без Claude Code; тесты пришлось бы гонять вживую.
- **Почему нет:** нужен путь для чужого ключа и для проверки без модели.

## Последствия

### Хорошее

- Отчёт на сдачу пересобирается из репозитория одной командой без модели: `--backend replay --replay <папка>/run`.
- Записанные живые прогоны на трёх форматах проверяются в CI снапшотом (`tests/test_e2e_replay.py`) без сети.
- Номер вызова входит в ключ запроса: три одинаковых прохода не получают из кеша один и тот же ответ.

### Плохое

- Путь через API вживую не запускали: он проверен только тестами на записанных синтетических ответах (`tests/test_llm_api.py`). Это написано в README.
- Две реализации живого вызова нужно держать в согласии: модель, effort, схема, разбор ошибок.

### Риски

- Изменился промпт или документ: replay находит ответ только по паре «шаг, номер вызова» и честно предупреждает `LLM-016`; снапшот e2e это ловит.
- Лимит подписки посреди прогона: `LLM-002` без повтора, шаги идут по своей политике отказа, отчёт пишется.
