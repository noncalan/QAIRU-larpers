# ADR-0006: PDF-движок за интерфейсом из-за AGPL

**Дата:** 2026-11-25 (записано задним числом 2026-11-26)
**Статус:** принято
**Кто решал:** команда по [исследованию 04](../research/04-parsing-and-broken-files.md), раздел «AGPL: проблема ли для нас»; движки сделаны в #26 и #33
**Журнал:** отдельной записи D-xxx нет

## Контекст

PDF — обязательный формат входа (ТЗ п. 3), и отчёт на сдачу делаем по PDF. Лучший по качеству и скорости движок PyMuPDF распространяется под AGPL-3.0. Для открытого репозитория хакатона это не помеха. Для банка, который захочет встроить агента во внутренний сервис, AGPL — красный флаг: изменённый код пришлось бы раскрыть или покупать коммерческую лицензию. Кроме того, готовый текст PyMuPDF (`get_text`) на нашем PDF ставит пробел перед знаками препинания, а это ломает сверку цитат.

## Решение

Движок спрятан за интерфейсом `PdfBackend` ([`ingest/pdf_backends.py`](../../src/validator/ingest/pdf_backends.py)) с двумя реализациями: `mupdf` (PyMuPDF, AGPL, по умолчанию) и `pdfium` (pypdfium2, без копилефта). Движок отдаёт только символы с координатами и линейки страницы. Строки, абзацы, заголовки, колонтитулы и таблицы собирает общий код ([`pdf_layout.py`](../../src/validator/ingest/pdf_layout.py), [`pdf_tables.py`](../../src/validator/ingest/pdf_tables.py)), поэтому оба движка дают один канонический текст. Переключение: `--pdf-backend pdfium` или переменная `VALIDATOR_PDF_BACKEND`.

## Альтернативы

### Только PyMuPDF и его готовый текст

- **Плюсы:** меньше кода, быстро.
- **Минусы:** AGPL без выхода для банка; пробелы перед знаками ломают цитаты.
- **Почему нет:** обе проблемы решает сборка текста своим кодом по символам.

### Только движок без копилефта

- **Плюсы:** нет вопроса лицензии.
- **Минусы:** на хакатоне терять лучший движок незачем.
- **Почему нет:** AGPL совместим с открытым репозиторием, а выбор остаётся у пользователя.

## Последствия

### Хорошее

- Банк может работать без AGPL одним флагом, остальной конвейер не меняется.
- Тесты разбора PDF идут на обоих движках и сравнивают их текст (`tests/test_ingest_pdf.py`).

### Плохое

- Своя сборка строк, абзацев и таблиц — больше кода, который надо поддерживать.
- Файла лицензии в репозитории пока нет; перед публикацией нужно выбрать лицензию, совместимую с AGPL, и упомянуть зависимость в README.

### Риски

- Парсеры расходятся на редких PDF (лигатуры, повёрнутый текст). Разница видна в тестах на двух движках; по умолчанию остаётся `mupdf`.
