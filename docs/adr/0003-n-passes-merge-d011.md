# ADR-0003: N проходов поиска со слиянием кодом, по умолчанию один проход (правило D-011)

**Дата:** 2026-11-26
**Статус:** принято по записанному правилу, ждёт подтверждения Нурдаулета
**Кто решал:** Нурдаулет (D-009: код поддерживает N проходов, три включаем только при приросте); выбор числа проходов сделало правило D-011 кодом
**Журнал:** D-009, D-011 в [`docs/decisions.md`](../decisions.md)

## Контекст

Модель между прогонами находит разное: у одного промпта число находок гуляет от 39 до 54. Несколько независимых проходов и слияние со счётчиком «найдено в N из K» дают стабильность и сигнал надёжности (3 из 3 надёжно, 1 из 3 повод перепроверить), но стоят дороже. Чтобы не решать «на глаз» после того, как увидели цифры, правило выбора записали в [`docs/plan.md`](../plan.md) до прогонов: три прохода по умолчанию, только если доля сверенных цитат у трёх проходов не ниже, чем у одного, и есть прирост стабильности (Жаккар +0,10), критичных (+10 п. п.) или recall (+5 п. п.).

## Решение

Код поддерживает N проходов ([`search.py`](../../src/validator/search.py), до трёх параллельно, `--passes 1…9`). Слияние ([`merge.py`](../../src/validator/merge.py)) склеивает находки по трём условиям сразу: общий блок, перекрытие цитат в документе не меньше 0,6, совместимое свойство; свойство, тип и вердикт решает большинство проходов; ничего не отбрасывает. По умолчанию один проход (профили `standard` и `submit`, `PROFILES` в [`config.py`](../../src/validator/config.py)): так решило правило D-011, которое применил код ([`evals/checkpoint.py`](../../evals/checkpoint.py)).

| | 1 проход (B) | 3 прохода (C) |
|---|---|---|
| Recall / строгий | 88,9 % / 71,9 % | 92,6 % / 80,0 % |
| Цитаты модели сверены | 100 % (194 из 194) | 99,4 % (335 из 337) |
| Жаккар находок между прогонами | 0,506 | 0,621 |
| Цена прогона по тарифу API | $1,50 | $2,86 |

Прирост Жаккара +0,115 есть, но обязательное условие по цитатам не выполнено (две цитаты из 337), поэтому один проход.

## Альтернативы

### Три прохода по умолчанию

- **Плюсы:** стабильнее (+0,115 Жаккара), строгий recall +8,1 п. п., почти за то же время (проходы параллельны).
- **Минусы:** примерно в 1,9 раза дороже; не прошло записанное правило.
- **Почему нет:** пороги не меняем после того, как увидели цифры (D-011, п. 4). Особое мнение Claude записано в D-011: обе «несверенные» цитаты — показ строки таблицы, а не выдумка модели.

### Разные «линзы» для проходов (разные промпты)

- **Плюсы:** могли бы находить разное.
- **Минусы:** «найдено в N из K» перестаёт значить согласие независимых проходов.
- **Почему нет:** включаем, только если eval покажет выигрыш (final-idea), замера нет.

## Последствия

### Хорошее

- Решение принято по правилу, записанному до прогонов, и воспроизводимо (`evals/checkpoint.sh`).
- `--passes 3` остаётся одной опцией; «найдено в N из K» и выбор находок для критика по «1 из K» работают без правок.

### Плохое

- С одним проходом «найдено в N из K» всегда 1 из 1, сигнал надёжности пропадает.
- Один проход менее стабилен между прогонами (Жаккар 0,51).

### Риски

- Если Нурдаулет решит мерить условие по цитатам с допуском, это изменение правила: записать в D-011 и поменять `PROFILES`.
