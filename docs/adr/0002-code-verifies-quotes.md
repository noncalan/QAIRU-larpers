# ADR-0002: Цитаты, важность и счётчики проверяет код, а не модель

**Дата:** 2026-11-25 (записано задним числом 2026-11-26)
**Статус:** принято
**Кто решал:** Нурдаулет (D-009, идея «Ревью с доказательствами»)
**Журнал:** D-009 в [`docs/decisions.md`](../decisions.md), CLAUDE.md, правило 4

## Контекст

Замер базовой линии ([исследование 11](../research/11-baseline-one-prompt.md)): один простой промпт к Opus 5.5 находит около 87 % дефектов эталона, но только 71,8 % его цитат дословно есть в документе, а число находок гуляет от 39 до 54 между прогонами. На контрольной точке 26.11 у одного промпта сверено 84,7 % цитат ([D-011](../decisions.md)). Лиду QA, который читает отчёт, выдуманная цитата хуже пропущенного дефекта: после неё он не верит остальному.

## Решение

Модель только предлагает: где требования, какие дефекты, какой сценарий, какой вопрос. Решения, от которых зависит доверие к отчёту, принимает код без модели:

- верификатор ([`verify.py`](../../src/validator/verify.py)) сверяет каждую цитату с документом через `text.locate_quote`: точно, затем нечётко (rapidfuzz ≥ 90), иначе «не найдено». В отчёт идёт фрагмент из документа, а не текст модели. Находка без сверенной цитаты уходит в «отброшено» с причиной;
- нарезка: модель называет ID блоков, а текст требования и якорь строит код («модель указывает, код цитирует»);
- важность считает таблица «тип дефекта × мешает ли написать тест-кейс» ([`severity.py`](../../src/validator/severity.py)); подсказка модели может только подтвердить или ограничить её;
- номера `R-NN`, `F-NN`, `Q-NN`, все счётчики сводки и светофор считает код;
- свидетель, критик находок и критик вопросов снимают или меняют что-то, только если код сверил их цитату-основание.

## Альтернативы

### Доверять модели и просить цитаты строже

- **Плюсы:** проще, дешевле.
- **Минусы:** промпт снижает, но не убирает выдуманные цитаты (84,7 % у одного промпта на контрольной точке).
- **Почему нет:** без проверки кодом нет гарантии, только надежда.

### Встроенные цитаты Claude API (Citations)

- **Плюсы:** модель сама возвращает точный фрагмент и его позицию.
- **Минусы:** только через API (у нас подписка, D-009), несовместимы со строгим JSON в одном вызове (по документации, сами не проверяли), не решают важность и счётчики.
- **Почему нет:** свой верификатор нужен в любом случае; Citations остаются идеей к финалу.

## Последствия

### Хорошее

- Цитаты итоговых находок сверены на 100 % на всех записанных прогонах (MD, PDF, DOCX: [`evals/results/2026-11-26-formats.md`](../../evals/results/2026-11-26-formats.md)).
- Важность и светофор воспроизводимы и объяснимы: отчёт показывает правило светофора, а как код посчитал важность каждой находки, записано в `report.json` (`Finding.severity_basis`).
- Отчёт проверяет сам себя ([`report/selfcheck.py`](../../src/validator/report/selfcheck.py)): находка без якоря или несошедшийся счётчик дают `INT-003` и код 1.

### Плохое

- Настоящий дефект с неточной цитатой теряется (уходит в «отброшено»). Отчёт показывает отброшенные и причину, но в основную таблицу они не идут.
- Таблица важности общая и грубая: по разметке precision находки «незначительно» разметчики сочли спорными ([#49](../../evals/results/2026-11-26-precision-pilot-e2e-md.md)).

### Риски

- Цитата строки таблицы в виде «Колонка: значение; …» не находится в тексте. Свидетель и критик уже сверяют такие цитаты по ячейкам; для верификатора это кандидат на доработку (D-011, «Найдено по пути»).
