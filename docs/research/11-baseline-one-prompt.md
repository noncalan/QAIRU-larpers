# 11. Базовая линия «один промпт» и `claude -p` как способ вызова модели

Автор: helknow (с Claude Code), 25.11.2026. Issue #2, задачи А и Б.
Скрипты: `experiments/11-baseline-one-prompt/` (`run_baseline.py`, `cli_backend_check.py`, `cli.py`, `score_quotes.py`). Сырые ответы: `experiments/out/11/` (в git не попадают).

## TL;DR

- Один хороший промпт к Opus 5.5 без всякой подготовки находит **в среднем 87,4 % дефектов эталона (39,3 из 45)** и **100 % критичных (9 из 9) во всех трёх прогонах**. Объединение трёх прогонов даёт 95,6 % (43 из 45). Планка для агента высокая: «просто промпт» уже очень силён по полноте.
- Слабые места базовой линии не в полноте, а в **проверяемости и стабильности**: **71,8 % цитат дословно есть в документе** (после нормализации разметки), ещё 13 % с правками, **15 % не находятся**. Число находок гуляет от 39 до 54 за прогон; 35 из 45 дефектов найдены во всех трёх прогонах.
- Один прогон: **118–185 с (в среднем 148 с)**, **расчётная стоимость $0,29–0,40 (в среднем $0,34)**, 12,7–19,9 тыс. выходных токенов. Почти всё время и деньги уходят на вывод.
- `claude -p` как бэкенд годится, **если соблюдать три правила**: `--safe-mode` обязателен (без него модель видит `~/.claude/CLAUDE.md`); на Windows нужен UTF-8 в stdin (из Python работает как есть, в PowerShell 5.1 нужен `$OutputEncoding`); ошибки входа приходят в JSON на stdout, а не в stderr.

## Условия опыта

| Параметр | Значение |
|---|---|
| Claude Code | 2.1.300 (Windows 11), вход по подписке; `ANTHROPIC_API_KEY` из окружения убирался |
| Модель (из `modelUsage` ответа) | `claude-opus-5-5` |
| Вызов | `claude -p --model opus --tools "" --system-prompt <...> --no-session-persistence --output-format json --safe-mode`; список аргументов через `subprocess`, текст запроса через stdin (UTF-8); пустая временная папка вне репозитория; `--bare` не использовался |
| Системный промпт | «Ты аналитик требований к программному обеспечению. Отвечай на русском языке.» |
| Документ | `data/input/requirements.md`, 13 705 байт |
| Прогонов | 3 независимых, последовательно, одинаковый запрос повторно не отправлялся |

Текст промпта (точно):

> Проверь документ требований по ISO/IEC/IEEE 29148:2018 (п. 5.2.5 и 5.2.6) и IEEE 830-1998 (п. 4.3). Выпиши все дефекты. Для каждого: точная цитата из документа, какое свойство нарушено, почему, насколько критично.

В запросе нет подсказок из эталона и примеров из документа. Эталон читал только оценщик (отдельный субагент), в промпт он не попадал.

## Задача А. Результаты

### Полнота

Эталон: 45 дефектов, из них «Критично» 9, «Средне» 21, «Низко» 15 (метки самого файла эталона).
Сопоставление выполнено семантически одним оценщиком (Claude). «Пограничные» совпадения (половина двухчастного дефекта или упоминание вскользь) показаны отдельно.

| Метрика | Прогон 1 | Прогон 2 | Прогон 3 | Среднее |
|---|---|---|---|---|
| Находок у модели | 52 | 39 | 54 | 48,3 |
| Дефектов эталона найдено | 39 | 39 | 40 | 39,3 |
| **Recall, всего (из 45)** | 86,7 % | 86,7 % | 88,9 % | **87,4 %** |
| Recall без пограничных совпадений | 77,8 % | 84,4 % | 84,4 % | 82,2 % |
| **Recall по критичным (из 9)** | 100 % | 100 % | 100 % | **100 %** |
| Критичные без пограничных | 88,9 % | 100 % | 100 % | 96,3 % |

Разбивка recall по уровням «Средне» и «Низко» лежит в локальном `experiments/out/11/score_summary.json`.

Самооценка критичности: «критичными» модель пометила 5, 1 и 4 находок по прогонам (прогон 2 использовал другую шкалу и почти не применял слово «критично»). Из этих 10 находок 9 попали в критичные дефекты эталона. Ранжирует модель разумно, но шкалу каждый раз выбирает сама. В прогонах 1 и 3 итоговые счётчики серьёзности в её сводке не совпадают с её же таблицей: счётчики должен считать код, а не модель.

### Находки вне эталона

| | Прогон 1 | Прогон 2 | Прогон 3 | Среднее |
|---|---|---|---|---|
| Находок, не попавших в эталон | 8 | 1 | 8 | 5,7 |
| из них настоящие дефекты документа | 6 | 0 | 5 | 3,7 |
| из них шум/пожелания | 2 | 1 | 3 | 2,0 |

Доля находок, сопоставленных с эталоном: 84,6 %, 97,4 %, 85,2 %. Деление «настоящий дефект / шум» — суждение оценщика по тексту документа. Настоящие лишние находки в основном мелкие. Мелкие замечания внутри совпавших находок отдельно не считались, поэтому число настоящих лишних дефектов слегка занижено.

### Стабильность по трём прогонам (45 дефектов эталона)

|---|---|---|
| всех 3 прогонах | 35 | 31 |
| ровно 2 | 5 | 7 |
| ровно 1 | 3 | 4 |
| ни в одном | 2 | 3 |
| Объединение трёх прогонов | 43/45 = 95,6 % | 42/45 = 93,3 % |

Все 9 критичных найдены во всех трёх прогонах.

### Цитаты (проверка кодом `experiments/03-proto/quote_check.py`)

«Дословно» считается после нормализации верификатора (разметка Markdown, виды кавычек и тире, регистр, пробелы), а не побайтово. Числа воспроизведены повторным запуском `score_quotes.py`.

| Прогон | Цитат | Дословно | С правками (fuzzy) | Не найдено | Дословно, % | Дословно + fuzzy, % |
|---|---|---|---|---|---|---|
| 1 | 73 | 57 | 6 | 10 | 78,1 | 86,3 |
| 2 | 85 | 58 | 12 | 15 | 68,2 | 82,3 |
| 3 | 104 | 73 | 16 | 15 | 70,2 | 85,6 |
| **Всего** | 262 | 188 | 34 | 40 | **71,8** | **84,7** |

По типу выделения: «ёлочки» 250 (181 / 34 / 35), обратные кавычки 7 (все дословно), блок-цитаты без «ёлочек» 5 (все не найдены). Из 40 ненайденных у 14 лучшее частичное совпадение ≥ 80, у 14 между 60 и 80, у 12 ниже 60. Границу между «собственной формулировкой модели в кавычках» (например, предложенная правка) и настоящей выдумкой я не проводил, поэтому 15 % — верхняя оценка.
**Вывод для правила 4 («каждая находка с цитатой»):** без проверки кодом примерно каждая шестая-седьмая цитата базовой линии не найдена в документе. Верификатор цитат нужен обязательно.

### Уточняющие вопросы автору

Модель не оформляла вопросы автору отдельным списком: все находки — утверждения. Вопросительные предложения внутри текста находок (по знаку «?»): прогон 1 — 0; прогон 2 — 1 (тип «объём/процесс»); прогон 3 — 9 (4 «неоднозначный термин», 5 «объём/процесс»). Вопросов «не хватает значения или порога» нет. Неявные маркеры «неясно/не ясно» встречаются 20, 4 и 14 раз (простой текстовый поиск, без классификации).
Вывод: если режим «вопросы автору» нужен, его надо просить в промпте и в схеме отдельным полем.

## Задача Б. `claude -p` как бэкенд вызова модели (Windows 11)

Всего 8 вызовов модели (плюс один нарочно без входа, до модели он не дошёл). Вход по подписке работал во всех обычных вызовах.

| № | Проверка | Результат | Что учесть в коде агента |
|---|---|---|---|
| 1 | Строгий JSON (`--json-schema`, схема `{defects:[{quote, property, explanation}]}`, первый раздел документа) | Работает: код 0, валидный объект лежит в поле **`structured_output`** ответа; он же продублирован строкой JSON в `result`. Разобран через pydantic без ошибок, 16 находок. 30,5 с, $0,09 | Читать `parsed["structured_output"]`, а не `result`; всё равно прогонять через pydantic |
| 2 | Кириллица: Python → stdin → ответ (тест-строка с `Ё ң ә ғ қ ө ұ ү һ і № ₸ « » —`) | Дословно совпала | `subprocess.run(..., input=text.encode("utf-8"))`, `PYTHONUTF8=1`, stdout декодировать как UTF-8 |
| 3 | Кириллица через PowerShell 5.1 (`Get-Content \| claude -p`) | **Испорчена**: модель получила `?` вместо букв. Пустой `--tools '""'` при этом принят | Не звать `claude` из PowerShell-конвейера без настройки кодировки; из Python проблемы нет |
| 3b | То же с `$OutputEncoding = [Text.Encoding]::UTF8` | Дословно совпало | В PowerShell 5.1 кодировку канала в нативную программу задаёт `$OutputEncoding`, а не `[Console]::OutputEncoding` |
| 4 | Два одновременных вызова (короткие промпты) | Оба успешно, по 4,9 с, **полностью параллельно** (перекрытие 4,9 с), без очереди и ошибок | Минимум 2 параллельных вызова работают; большие ответы и больше 2 вызовов не проверены |
| 5 | Вызов без входа (пустой `CLAUDE_CONFIG_DIR`) | **Код возврата 1**, stderr пуст. JSON на stdout: `is_error: true`, `result: "Not logged in · Please run /login"`, `terminal_reason: "api_error"`, стоимость 0 | Причину ошибки читать из JSON stdout (`is_error`, `result`), не из stderr; код ≠ 0 тоже ловить |
| 6 | «Видишь ли ты файлы или инструкции проекта?» **с `--safe-mode`**, пустая папка | Ответ «НЕТ»: файлов, `CLAUDE.md`, памяти и скиллов не видит | Рабочий режим для агента |
| 7 | То же **без `--safe-mode`** | Ответ «ДА»: модель пересказала глобальный `~/.claude/CLAUDE.md` пользователя | **`--safe-mode` обязателен**: иначе личные инструкции попадают в проверку, а результат не воспроизводится у жюри |

Ограничения и нерешённое:
- Превышение лимита подписки намеренно не провоцировали: что вернёт команда в этом случае, неизвестно.
- Флаги `--safe-mode`, `--no-session-persistence`, `--tools`, `--json-schema` есть в `claude --help` версии 2.1.300 (в issue упомянута 2.1.332). У жюри версия может отличаться: агент должен проверять наличие флагов и выдавать понятную диагностику.
- Параллельность проверена на двух коротких вызовах. Поведение при 5–10 одновременных больших вызовах не проверено.
- Время одиночного вызова на документе 13 КБ: 118–185 с на полный разбор (см. задачу А); 30 с на один раздел со строгой схемой.
- Даже с `--safe-mode` модель в проверке 6 упомянула строку встроенного системного промпта про Claude Agent SDK. От проектных инструкций контекст чист, от встроенных инструкций Claude Code — нет.
- На Windows временная папка после вызова удаляется не сразу (процесс ещё держит её): очистку делаем с `ignore_cleanup_errors=True` (в `cli.py` исправлено).

## Рекомендации для агента

1. Планка: промпт без подготовки уже даёт ≈87 % recall и 100 % критичных. Сложность (нарезка на требования, линтер, несколько проходов) нужна ради того, что базовая линия делает плохо: **проверяемые цитаты (72 % дословных), стабильность между прогонами, структурированный отчёт и воспроизводимость**, а не ради «найти больше».
2. Верификатор цитат кодом обязателен; находки без найденной цитаты понижать или помечать.
3. Бэкенд на время разработки: `claude -p --safe-mode --tools "" --output-format json` из Python списком аргументов; запрос через stdin в UTF-8; строгий JSON через `--json-schema` и поле `structured_output`; кеш ответов на диск по хешу запроса; ошибки разбирать по JSON stdout.
4. Один полный прогон — около 2,5 минут и ≈ $0,34 по расчёту; вызов по частям (на раздел ≈ 30 с) даёт меньшую задержку и распараллеливается.
5. Вопросы автору просить явно, отдельным полем.

## Что не проверено

- Сопоставление с эталоном делал один оценщик (Claude) без второго мнения; 7 из 118 совпадений на уровне прогонов пограничные (см. цифры «без пограничных»). Для строгого результата нужна независимая перепроверка.
- Один документ и три прогона: доверительных интервалов нет.
- Лимиты подписки и поведение при их исчерпании.
- Встроенные цитаты, кеширование префикса, PDF-вход: нужен ключ API (issue #5).
