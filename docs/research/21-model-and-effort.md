# 21. Какую модель Claude и какой effort ставить на каждый шаг агента

Автор: Claude (поток «Выбрать модель и effort для агента»), 25.11.2026.
Скрипты: `experiments/21-model-effort/` (`run_matrix.py`, `score.py`). Сырые ответы: `experiments/out/21/` (в git не попадают). Решение: D-010 в `docs/decisions.md`.

## TL;DR

- **Формат ответа важнее выбора модели.** Если заставить модель сразу отвечать строгим JSON (`claude -p --json-schema`), она думает в 3–5 раз меньше и находит меньше. Opus 5.5 на effort `medium`: 73 % эталона в JSON против 93 % свободным текстом. Поэтому проходы поиска пишут обычный текст, а в JSON его переносит отдельный дешёвый вызов.
- **Перенос в JSON делает Haiku 5.5 почти бесплатно и без потерь.** Haiku (`medium`) переложил ответ Opus в JSON: ни одна находка не потерялась, 100 % цитат дословно есть в документе (в свободном тексте самого Opus дословных 68–83 %). Стоимость $0,026 за проход.
- **Для трёх проходов поиска лучший выбор: Opus 5.5, свободный текст.** На `medium` один проход находит в среднем 92,6 % эталона, объединение трёх проходов 100 % (строго 95,6 %), $0,28 и ≈2 мин на проход. На `xhigh` один проход 97 %, объединение 100 % (строго 100 %), но $0,80 и до 7,5 мин на проход.
- **Fable 5.2 не нужен.** На нашем документе он не лучше Opus (свободный текст: 95,6 % против 92,6–97 %), стоит вдвое дороже по API, на тарифе Pro доступен только за платные кредиты, на Max съедает до половины недельного лимита.
- **Sonnet 5.5 хорош, но почти не дешевле.** В свободном тексте Sonnet `high` дал 93,3 % за $0,26, Opus `medium` 92,6 % за $0,28: Sonnet думает дольше и тратит столько же токенов.
- **Haiku 5.5 как искатель слабый, как помощник отличный.** Строго он находит 47–67 % (Opus 83–90 %), больше шума, один раз пропустил критичный дефект. На подсобных шагах (перенос в JSON, проверка формата) он лучший по цене.
- **Цена полного прогона агента по API:** около $1,6 при проходах на `medium`, около $3,2 на `xhigh` (часть шагов оценена, см. раздел «Цена»). На $5 это 3 прогона или 1, на $20 это 12 или 6. 94–97 % цены прохода составляет вывод модели, поэтому кеширование документа почти ничего не даёт. Экономят effort, перенос в JSON через Haiku, разработка через подписку и replay.

Чтобы в контекст не попали чужие настройки, из окружения дочернего процесса убирались `ANTHROPIC_API_KEY`, `CLAUDE_EFFORT` (в облачной сессии он задан как `xhigh`), `CLAUDE_ADDITIONAL_DIRECTORIES` и `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD`. Контрольный вопрос показал: `CLAUDE.md`, эталона и файлов проекта модель не видит, но встроенные блоки Claude Code (окружение, атрибуция git) остаются. Они одинаковы для всех прогонов.

**Recall** ниже считается как доля 45 дефектов эталона, которые судья отметил found или partial. **Строгий recall** считает только found. «Критичные»: 9 дефектов с меткой «Критично». **Объединение**: дефекты, найденные хотя бы в одном из прогонов этой конфигурации, то есть то, что дадут несколько проходов агента.

### Почему JSON проигрывает

В режиме JSON модель тратит на размышление в 3–5 раз меньше токенов: Opus `high` 3,6–5,8 тыс. против 22,5 тыс. в тексте, Opus `medium` 2,4 тыс. против 4,5–5,6 тыс. плюс длинный разбор в самом ответе. В `claude -p` схема реализована через вызов инструмента (в ответе `num_turns: 2`, `stop_reason: tool_use`): модель пишет находки сразу в аргумент инструмента и не рассуждает над документом вслух. Через API (`output_config.format`) это не проверяли: нужен ключ, тема 19.

### Насколько можно доверять судье

Повторная оценка тех же четырёх ответов тем же судьёй совпала в 178 из 180 вердиктов, recall разошёлся максимум на 1 дефект. Разброс в таблицах даёт модель-искатель, а не судья. Но судья один, это Opus, и эталон тоже составлял Claude, поэтому возможен перекос в пользу Opus. Числа на одном документе, по 1–3 прогона на конфигурацию: разницу в 2–3 пункта считать шумом.

Сравнение с исследованием 11: там Opus 5.5 свободным текстом дал 87,4 % (другой судья, effort по умолчанию на машине helknow). Наш Opus `medium` в тексте даёт 92,6 % с нашим судьёй. Числа разных судей напрямую не сравниваем.

### Как не платить лишнего и не терять качество

1. **Разработка и eval через подписку** (`claude -p`, D-008), ключ API только для финальных прогонов. Тогда по API нужно 2–4 прогона, то есть $3–13.
2. **Кеш ответов и replay.** Повторная сборка отчёта из лога стоит $0, жюри тоже пересобирает его без ключа.
3. **`medium` вместо `xhigh` на проходах:** втрое дешевле и в 2,8 раза быстрее, объединение трёх проходов на нашем документе то же (100 %, строго 95,6 % против 100 %). `xhigh` включаем один раз на отчёт для сдачи.
4. **Перенос в JSON через Haiku, а не Sonnet:** $0,026 против $0,17 за проход при одинаковом результате.
5. **Не Fable:** вдвое дороже Opus и без выигрыша. Sonnet вместо Opus на проходах почти не экономит ($0,26 против $0,28) и чуть хуже.
6. **Batch API (скидка 50 % на все токены)** для eval по эталону, холдауту и мутациям: ответ приходит не сразу, поэтому не для живого демо (по справке SDK на 03.11.2026, сами не проверяли).
7. **Кеширование документа (prompt caching) включаем, но оно почти ничего не даёт:** документ около 6 тыс. токенов, это около 3–6 % цены прохода, остальное вывод.
8. **Если денег совсем мало:** два прохода вместо трёх дают 42–45 из 45 на `medium`. Для отчёта на сдачу не советуем.
9. **Ограничитель расходов:** в `claude -p` есть `--max-budget-usd`, в коде с API считаем стоимость по `usage` после каждого вызова, останавливаемся на пороге и пишем это в паспорт прогона.

## Подписка: лимиты и практические детали

- **Fable на подписке.** На Pro модели Fable не входят в лимиты тарифа и оплачиваются кредитами с первого вызова; на Max на них можно тратить до 50 % недельного лимита, и они расходуют лимит быстрее других моделей ([справка Claude](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan), прочитано 25.11.2026). У helknow тариф Pro, поэтому Fable в `claude -p` у него стоил бы денег.
- **Opus и Sonnet.** Opus расходует квоту заметно быстрее Sonnet ([справка Claude Code](https://support.claude.com/en/articles/14552983-models-usage-limits-in-claude-code), прочитано 25.11.2026, точного множителя там нет). Один прогон агента на `medium` по ценам API ≈ $1,6, поэтому на Pro разумно гонять eval умеренно и с кешем.
- **Флаги.** В Claude Code 2.1.332 есть `--model` (алиасы `opus`, `sonnet`, `haiku`, `fable` или полное имя) и `--effort low|medium|high|xhigh|max`. В коде агента передаём **полные имена** (`claude-opus-5-5` и т. п.): алиас переедет на новую модель, и паспорт отчёта перестанет совпадать с прогоном.
- **Переменная `CLAUDE_EFFORT`** в окружении может задавать effort за нас. Агент убирает её из окружения дочернего процесса и передаёт `--effort` явно.
- **Значения по умолчанию в API разные:** у Opus 5.5 и Haiku 5.5 `medium`, у Sonnet 5.5 и Fable 5.2 `high`. Поэтому effort задаём в каждом вызове явно (`output_config.effort`). Отключить размышление у Opus 5.5 нельзя, управлять можно только effort (по справке SDK на 03.11.2026).

## Риски и непроверенное

- Один документ, 1–3 прогона на конфигурацию, один судья (Opus). Числа годятся для выбора, но не для обещаний жюри. Перед сдачей стоит повторить замер на холдауте (исследование 20).
- Эффект «JSON думает меньше» замерен для `claude -p --json-schema`. Через API со строгим JSON (`output_config.format`) может быть иначе, проверить вместе с темой 19, когда появится ключ.
- Шаги, кроме проходов поиска и переноса в JSON, не замерялись: выбор модели там по смыслу задачи.
- Время замерено при 3–5 параллельных вызовах из облачного контейнера. На Windows и при большем числе параллельных вызовов может отличаться (у helknow проверено 2 параллельных вызова).
- `xhigh` даёт большой разброс времени: 255–450 с на проход. На живом демо надёжнее `medium` или replay.
