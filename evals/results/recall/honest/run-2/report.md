### Какие вопросы задать автору первыми

1. **Q-01** · P0 (блокирует разработку) · кому: архитектор: Владелец карты вызывает сохранение с amount=999 или enabled=2: какой HTTP-код возвращает метод?
   - Варианты: A. Код 200, в теле result=ERROR; B. Код 400 для любой неверной суммы или enabled, код 200 только при result=OK; C. Код 400 при отсутствии или неверном формате параметра, код 200 с ERROR при целой сумме вне 1 000–1 000 000
2. **Q-02** · P0 (блокирует разработку) · кому: бизнес: Расходы 49 000 ₸, порог 50 000 ₸, покупку на 2 000 ₸ авторизовали 10 марта, клиринг прошёл 12 марта: в какой день она входит в расходы и вызывает push?
   - Варианты: A. 10 марта, при авторизации; отменённая авторизация уменьшает расходы; B. 12 марта, при клиринге
3. **Q-03** · P0 (блокирует разработку) · кому: архитектор, аналитик: Клиент открывает экран «Уведомления» для карты: каким вызовом приложение получает текущий порог, переключатель и сумму за месяц?
   - Варианты: A. Отдельным методом чтения, который описывается в части B; B. Тем же методом: вызов без amount и enabled возвращает текущую настройку и сумму за месяц; C. Сумма за месяц на экране не показывается, порог и переключатель читаются отдельным методом
4. **Q-04** · P0 (блокирует разработку) · кому: архитектор: Сохранение изменяет порог карты: оставить GET с параметрами в строке запроса или передавать amount и enabled телом JSON другим методом?
   - Варианты: A. GET с query-параметрами; заголовок Content-Type не требуется; B. PUT или POST с телом JSON {amount, enabled} и заголовком Content-Type: application/json
5. **Q-05** · P0 (блокирует разработку) · кому: архитектор: У карты сохранён порог 30 000 ₸, метод отклоняет amount=500: какие поля содержит тело ответа?
   - Варианты: A. Только result=ERROR и message; B. result=ERROR, message и прежние amount и enabled; C. Только message, без result, во всех неуспешных ответах

### Q-01 · P0 · архитектор · код ответа при ошибке
**Вопрос.** Владелец карты вызывает сохранение с amount=999 или enabled=2: какой HTTP-код возвращает метод?

**Где в документе.**
- «Ответ в случае, если параметры запроса заполнены неверно.» (раздел «Часть B. REST API › Статусы», строка 163)
- «{"result":"ERROR","message":"Проверьте сумму"}» (строка 171)

**Почему важно.** Пример ошибки суммы стоит под кодом 200, а код 400 описан для неверных параметров. От ответа зависят обработка в клиенте, мониторинг и ожидаемый код в тестах. Заодно закрывается перечень «400, 401 и далее».

| Вариант | Правило | Что поменять |
|---|---|---|
| A | Код 200, в теле result=ERROR | Перенести пример ERROR в описание 200; из описания 400 убрать отклонение суммы и enabled |
| B | Код 400 для любой неверной суммы или enabled, код 200 только при result=OK | Перенести пример ERROR под 400; в разделе «Статусы» дать закрытый перечень кодов |
| C | Код 400 при отсутствии или неверном формате параметра, код 200 с ERROR при целой сумме вне 1 000–1 000 000 _(вариант для обсуждения)_ | Описать в разделе «Статусы» оба случая и примеры тел |
| Другое | ___ | |

**Если не ответить.** Команда вернёт 200 с ERROR, как в примере; мониторинг посчитает ошибки ввода успешными вызовами.
