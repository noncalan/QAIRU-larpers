- «Когда расходы переходят от суммы ниже порога к сумме, равной порогу или выше, клиент получает push.» (раздел «Требования к изменениям › Функциональные требования», строка 39)
- «Если она ниже нового порога, следующее достижение вызывает push независимо от истории предыдущей настройки.» (раздел «Требования к изменениям › Функциональные требования», строка 40)

**Почему важно.** Ф-4 описывает только накопленную сумму ниже нового порога, а Ф-3 требует перехода снизу. От ответа зависит, вызывает ли сохранение настройки отправку push; то же правило действует при включении уведомления.

|---|---|---|
| A | Сразу после сохранения порога _(вариант для обсуждения)_ | Добавить в Ф-4: при сумме не ниже нового порога push отправляется при сохранении; добавить шаг в Sequence Diagram |

| C | В этом месяце не получит: push только при переходе снизу | Добавить в Ф-4 явное правило и критерий приёмки «push не отправляется» |
| Другое | ___ | |

**Если не ответить.** По Ф-3 push не будет до следующего месяца; клиент, задавший порог ниже потраченного, решит, что функция не работает.
