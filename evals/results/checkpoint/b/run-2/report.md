1. **Q-01** · P0 (блокирует разработку) · кому: архитектор: Клиент открыл экран «Уведомления»: каким методом приложение получает текущий порог, состояние переключателя и сумму за месяц?
   - Варианты: A. Отдельный метод чтения в части B возвращает порог, переключатель и сумму за месяц; saveLimit только сохраняет; B. Метод saveLimit без параметров amount и enabled возвращает текущие настройки и сумму; C. Порог и переключатель — новым методом части B, сумма за месяц — из сервиса учёта расходов
2. **Q-02** · P0 (блокирует разработку) · кому: бизнес: Покупка совершена 31 января в 23:58, а проведена 1 февраля в 00:03 по Алматы: в расходы какого месяца она попадает?
   - Варианты: A. В январь: месяц определяется по дате совершения покупки; B. В февраль: месяц определяется по дате проведения покупки
3. **Q-03** · P0 (блокирует разработку) · кому: архитектор: Запрос пришёл с amount=999, с enabled=2 или без amount: какой код и какое тело ответа получает приложение в каждом случае?
   - Варианты: A. Сумма вне 1 000–1 000 000 даёт 200 и ERROR «Проверьте сумму»; нет параметра, не число или enabled не 0/1 дают 400 «Некорректный запрос»; B. Любые неверные параметры, включая сумму вне диапазона, дают 400; C. Любые неверные параметры дают 200 с ERROR и описанием ошибки
4. **Q-04** · P0 (блокирует разработку) · кому: архитектор: Если для чужой и несуществующей карты метод возвращает 404, в каком случае он возвращает 403?
   - Варианты: A. 403 не используется; метод возвращает только 200, 400, 401, 404, 500; B. 403 возвращается, когда сессия действительна, но у пользователя нет права настраивать уведомления по своей карте; C. 403 возвращается для чужой карты, 404 только для несуществующей
5. **Q-05** · P0 (блокирует разработку) · кому: архитектор: Приложение сохраняет порог 50 000 ₸ для карты demo-42: каким методом HTTP и где передаются cardId, amount и enabled?
