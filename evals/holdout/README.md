### Можно ли верить разметчику

В каждую пачку код подмешал 5 заведомо ложных контрольных находок. Opus 5.5 пометил «ложный» все 5 из 5 на обоих документах (файлы precision выше, раздел «Контрольные ложные находки»). Оговорка: пачка на документ одна, поэтому все контрольные одного вида, «придирка без влияния на тест»; контрольных с подменённой цитатой нет ([`evals/README.md`](../README.md), раздел «Precision (#49)»). Находки писал Opus 5.5, и разметчик та же модель: без второго разметчика другой модели это оценка сверху.

### Как читать цифры

- **c4 близок к документу кейса.** На `requirements.md` та же разметка Opus 5.5 давала 49,5 % / 96,0 % по 99 находкам двух прогонов ([`evals/results/2026-11-26-precision-recall-v3.md`](../results/2026-11-26-precision-recall-v3.md), версия агента раньше текущей). На c4 вышло 61,8 % / 97,1 %: на чужом API-документе агент не стал заметно шумнее. Все 7 критичных находок c4 Opus назвал настоящими.
- **На ТЗ кейса находок слабее.** Строгая precision 28,1 %, 6 из 32 находок (19 %) разметчик счёл ложными, все 12 незначительных находок оказались «спорно» или «ложный». ТЗ кейса это короткое задание на хакатон, а не спецификация продукта: многие находки про порядок оценки и сдачи разметчик назвал пожеланиями. Это наблюдение, а не повод править промпт: правки по холдауту запрещены, кандидаты в правки перечислены в файле precision, раздел «Ложные по мнению всех разметчиков».
- Один прогон на документ, поэтому стабильность здесь не видна.

## Как шёл прогон

| Документ | Версия агента | Профиль | Вызовов модели | Время | Цена по тарифу API | Код возврата |
|---|---|---|---:|---:|---:|---:|
| `c4` | `e8ef344` (main, чистое дерево) | `standard`, 1 проход, `--backend cli`, `--max-budget-usd 5` | 8, сбоев 0 | 8,4 мин | $1,62 | 0 |
| `task` | `e8ef344` (main, чистое дерево) | то же | 8, сбоев 0 | 8,6 мин | $1,58 | 0 |

Источник: `passport` и `metrics` в `report.json` (`agent_version`, `agent_dirty: false`, `calls_total`, `calls_cached: 0`, `duration_s`, `cost_usd`). Все ответы модели живые, из кеша ни одного. Платили лимитом подписки, цена показана по тарифу API для сравнения. Сырые ответы модели лежат в `run/` каждого документа: по ним прогон повторяется без сети (`--backend replay --replay evals/holdout/<документ>/run`).

Команды:

```bash
uv run validator data/holdout/c4/c4_tech_task.md evals/holdout/c4/report.md --backend cli --profile standard --max-budget-usd 5
uv run validator data/holdout/task/task.md evals/holdout/task/report.md --backend cli --profile standard --max-budget-usd 5
uv run python -m evals.precision label evals/holdout/c4 --document data/holdout/c4/c4_tech_task.md \
  --name holdout-c4-opus-only --labelers opus --mode cache --out-dir evals/holdout/c4
uv run python -m evals.precision label evals/holdout/task --document data/holdout/task/task.md \
  --name holdout-task-opus-only --labelers opus --mode cache --out-dir evals/holdout/task
```

## Примеры находок для README и слайдов

Все три Opus 5.5 пометил «настоящий»; цитаты сверены с документом кодом и вручную.

1. **ТЗ кейса: формат входа противоречит выданному документу** (`task`, F-02, критично, [`task/report.md`](task/report.md)). Строка 13: «Проверяемый документ выдают организаторы отдельно» (дальше в скобках ссылка на `docs/requirements.md`), а строка 29: «Запускает агента и передаёт этот документ на вход (PDF + при поддержке других форматов)». Выдан Markdown, а обязательным назван PDF: команда может сделать поддержку не того формата. На kick-off это место споткнуло и самих организаторов: «Кстати, Аскар, я не помню мы в ПДФ формате в итоге рекверментсот дали или в МД» ([`docs/case/kickoff-transcript.md`](../../docs/case/kickoff-transcript.md), 14:13). Совпадение с вопросами участников судьёй не мерили, это ручное наблюдение по транскрипту.
2. **c4: кратность связи «сотрудник — компания» противоречит удалению** (`c4`, F-02, критично, [`c4/report.md`](c4/report.md)). Строка 27: «Привязка сотрудника к компании (1:1 или null).», строка 63: «Удалить компанию (если нет сотрудников).» Если связь 1:1, у компании не бывает «сотрудников» во множественном числе; от ответа зависят схема БД (уникален ли внешний ключ) и тест привязки второго сотрудника.
3. **c4: длина ИНН в тексте и в схеме OpenAPI расходится** (`c4`, F-16, важно). Строка 38: «`inn` (уникальный, 10/12 цифр)», а строка 111: «minLength = 10, maxLength = 12». Схема пропускает 11 цифр, которых по тексту быть не может: документация API будет описывать не то, что проверяет валидация.

## Что осталось

1. **Второй разметчик precision.** Когда Fable 5.2 будет доступна (кредиты на подписке или другая подписка), запустить без `--labelers` и `--mode`: ответы Opus возьмутся из кеша `evals/cache/precision/`, живыми будут только 2 вызова Fable (по одному на документ; вызов Opus на ту же пачку шёл меньше минуты):

   ```bash
   uv run python -m evals.precision label evals/holdout/c4 --document data/holdout/c4/c4_tech_task.md --name holdout-c4 --out-dir evals/holdout/c4
   uv run python -m evals.precision label evals/holdout/task --document data/holdout/task/task.md --name holdout-task --out-dir evals/holdout/task
   ```

2. **Сравнение вопросов с kick-off.** `uv run python -m evals.kickoff` (по умолчанию оба судьи, вопросы из `kickoff_questions.md`, прогон `evals/holdout/task`, результат в `evals/holdout/kickoff.{json,md}`). Это 2 живых вызова. Только с Opus: `--labelers opus`, тогда согласие судей останется «не измерено».
3. После этого заполнить в таблице столбцы «Precision два разметчика» и «Совпадение с kick-off» и перенести строку в README для жюри.
