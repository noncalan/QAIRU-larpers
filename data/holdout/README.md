## Почему эти четыре

- `c4` выбран в исследовании [20](../../docs/research/20-holdout-documents.md) (кандидат H4): документ с API, который можно законно положить в публичный репозиторий. Лицензия MIT в репозитории источника проверена 26.11.2026.
- `task` это само ТЗ кейса. Агент его при разработке не проверял: мы гоняли агента только по `data/input/requirements.md`. Зато к этому ТЗ есть живые вопросы участников на kick-off, и с ними можно сравнить вопросы агента ([`evals/holdout/kickoff_questions.md`](../../evals/holdout/kickoff_questions.md)).
- `repair-webapp` и `finuchet` найдены поиском по GitHub 26.11.2026 (слова «техническое задание», «ТЗ», «функциональные требования», фильтр по открытой лицензии). Брали только то, где лицензия MIT лежит в репозитории источника, а автор текста совпадает с владельцем репозитория. Хотели непохожие документы: `repair-webapp` это сырое продуктовое ТЗ с расплывчатыми формулировками, `finuchet` это аккуратное формальное ТЗ в PDF с числами и критериями проверки. Второй нужен, чтобы увидеть, не засыпает ли агент хороший документ придирками, и чтобы проверить на чужом документе обязательный по ТЗ кейса формат PDF.
- Все четыре документа выбраны **до** первого прогона агента на них и не менялись после. В таблицу результатов попали все прогоны, каким бы ни вышел результат.
- **Лицензия `task`.** В репозитории организаторов файла лицензии нет (GitHub API, 26.11.2026: `"license": null`). Это задание, которое организаторы опубликовали для всех участников; та же копия уже лежит в [`docs/case/task.md`](../../docs/case/task.md) (тело совпадает побайтово, там только добавлена строка об источнике). Если организаторы попросят, файл убираем, а в отчётах оставляем ссылку и короткие цитаты.
- Банковские ТЗ без лицензии из исследования 20 (H1, H2, H3) в репозиторий не кладём.

## Ограничения

- `c4` это учебное тестовое задание, `finuchet` учебное ТЗ студента колледжа, `task` написан для хакатона, `repair-webapp` ТЗ небольшого продукта. Настоящих ТЗ банков с открытой лицензией мы не нашли.
- Все четыре на русском, три в Markdown и один в PDF. Английский и смешанный документы проверены отдельно, без оценки качества находок: `reports/robustness/`. DOCX проверяем на документе кейса.
- Эталона дефектов у этих документов нет, поэтому полноту (recall) на них не считаем. Меряем precision по слепой разметке двумя моделями (#49) и долю сверенных цитат.
