## Как выбирали

- Поиск по GitHub 26.11.2026 по словам «техническое задание», «ТЗ», «функциональные требования» с фильтром по открытой лицензии. Список кандидатов из исследования [20](../../docs/research/20-holdout-documents.md) учтён: `c4` оттуда.
- Брали только то, что можно законно положить в публичный репозиторий: лицензия MIT в самом репозитории источника, автор текста совпадает с владельцем репозитория. Банковские ТЗ без лицензии (исследование 20, H1 и H2) не брали.
- Хотели разные документы: API без таблиц (`c4`), сырое продуктовое ТЗ с расплывчатыми формулировками (`repair-webapp`), аккуратное формальное ТЗ в PDF с числами и критериями проверки (`finuchet`). Третий нужен, чтобы увидеть, не засыпает ли агент хороший документ придирками.
- Документы выбраны **до** первого прогона агента на них и не менялись после. В таблицу результатов попали все три прогона, каким бы ни вышел результат.

## Ограничения

- Документы учебные и тестовые, а не банковские ТЗ: настоящих ТЗ банков с открытой лицензией мы не нашли.
- Все три на русском. Английский и смешанный документы проверены отдельно, без оценки качества находок: `reports/robustness/`.
- Эталона дефектов у этих документов нет, поэтому полнота (recall) на них не считается.
