# Исследовательский спринт

## 1. Проверь, что уже сделано

- Прочитай `docs/research/README.md` (индекс тем и владельцев) и открытые issues с меткой `research` (`gh issue list --label research`).
- Не бери темы, которые уже есть в индексе у другого человека. Если тема пересекается, сузь её и запиши в индексе, чем твоя отличается.

## 2. Разбей на подтемы

- 3–8 подтем, каждая отвечает на свой вопрос и не пересекается с остальными.
- Для каждой: номер файла, имя (`docs/research/<NN>-<тема>.md`), 3–6 подвопросов, что должно быть в выводах.
- Запиши план в индекс `docs/research/README.md` (статус «в работе»), чтобы другие видели.

## 3. Запусти субагентов параллельно

- Одним сообщением запусти по субагенту `researcher` на каждую подтему (так они работают одновременно). В промпт каждому дай: тему, подвопросы, путь к файлу, что не делать (не трогать чужие темы, не писать код агента).
- Практические эксперименты (скрипты, замеры) клади в `experiments/<тема>/`, результаты замеров в тот же файл исследования.
- Ключи берутся из `.env` через python-dotenv. Не выводи ключ в лог и не вставляй его в файлы.

## 4. Перепроверь

- На каждый готовый файл, где есть цифры, лимиты, цены или имена моделей, запусти `fact-checker`.

## 5. Собери итог

- Обнови `docs/research/README.md`: статус «готово», 2–3 строки главного по каждой теме.
- Если тебя просили итог, напиши `docs/research/<NN>-summary-<кто>.md`: что узнали, что это значит для выбора идеи, открытые вопросы.

## 6. Сдай через PR

- Ветка `research/<тема>`, коммит, PR с `Closes #<issue>` и списком файлов. В `main` напрямую не пушить.
- Перед коммитом проверь `git diff --staged`, что нет ключей и `.env`.
