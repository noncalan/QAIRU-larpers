# Доменные чек-листы

Общие чек-листы предметных областей с триггерами (issue #35). Чек-лист включается, только если в документе есть его сущность, иначе он шумит на чужих ТЗ.

| Файл | ID | Область | Пунктов |
|---|---|---|---|
| `1-money.yaml` | MON | Деньги и суммы | 6 |
| `2-datetime.yaml` | DT | Даты, время и периоды | 6 |
| `3-lifecycle.yaml` | LC | Статусы и жизненный цикл | 5 |
| `4-notifications.yaml` | NT | Уведомления | 5 |
| `5-api.yaml` | API | API и интеграции | 8 |
| `6-personal-data.yaml` | PD | Персональные данные и безопасность | 6 |

## Как работает

1. `select_checklists` ищет триггеры чек-листа (регулярные выражения общих слов области, без учёта регистра) в тексте каждого блока документа. Строки таблиц смотрим как в документе, без названий колонок: иначе одна таблица с колонкой «Дата» или «Статус» включила бы чек-лист сама.
2. Чек-лист включается, если триггеры встретились хотя бы в `min_blocks` блоках (у всех 2): одно случайное слово («цена» в описании каталога) чек-лист не включает.
3. Пункты включённых чек-листов идут в пользовательский промпт прохода поиска отдельным разделом после документа (`prompts/search_checklists.md`). Модель отмечает находку по пункту строкой «Чек-лист: <ID>»; код принимает только ID пунктов, которые были в промпте, и пишет его в источник находки (`FindingSource.checklist_item`).
4. В паспорт идут включённые чек-листы, в отчёт (раздел 5) все: включён или нет, в скольких блоках встретились слова области, примеры слов и находки с пунктом чек-листа. В воронке метрик видно, сколько кандидатов и находок отмечены пунктом.
5. `--no-checklists` выключает раздел в промпте; триггеры всё равно считаются и видны в отчёте.
6. Replay записи, сделанной без чек-листов (до #35 или с `--no-checklists`), сам выключает их, если в записи есть проход по ключу без раздела чек-листов, а с разделом нет (диагностика `LLM-005`, уровень «инфо»).

Если ни один чек-лист не включён, промпт прохода тот же, что до #35.

## Формат файла

```yaml
id: MON                 # 2–4 латинские буквы, префикс ID пунктов
title: Деньги и суммы
triggers:
  min_blocks: 2         # в скольких блоках должны встретиться слова области
  patterns:             # регулярные выражения Python, без учёта регистра; (?-i:…) с учётом
    - '\bсумм'
items:
  - id: MON-01          # <ID чек-листа>-NN
    property: SET-CONS  # код свойства стандарта (models.Property)
    question: …         # что проверить в документе
    why: …              # почему пробел мешает разработке и тесту
```

## Правила

- Только универсальные знания областей (платежи, даты, REST, персональные данные, тест-дизайн переходов состояний), без слов и формулировок проверяемого документа и без пунктов эталона (CLAUDE.md, правила 2 и 3). Пункты написаны с нуля по общим знаниям, эталон при этом не открывали; чек-лист исследования 09 не брали: его сверяли с эталоном.
- `tests/test_prompt_leak.py` проверяет эту папку: ни одной последовательности из 6 слов документа или эталона и ни одного слова из списка «хардкода».
- Правка пунктов или триггеров меняет промпт поиска: нужен прогон eval и цифра в PR (CLAUDE.md, правило 5).
